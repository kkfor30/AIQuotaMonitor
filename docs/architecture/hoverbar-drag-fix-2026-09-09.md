# 悬浮球按下拖动失去跟随修复

## 问题与证据

用户反馈：额度面板展开时按下小球并移动鼠标，小球可能留在原地或远离鼠标。

- 旧前端并发发送 `set_hoverbar_dragging(true)` 与 Tauri `startDragging`。隐藏详情和启动拖动没有完成顺序保证，迟到的展开回复还会追加隐藏请求。
- 本机锁定的 `tao 0.35.3` 中 `platform_impl/windows/window.rs::handle_os_dragging` 把局部 `POINTS` 地址传给 `PostMessageW(WM_NCLBUTTONDOWN)`。该消息 LPARAM 应为打包的屏幕坐标，不能使用临时对象地址；异步消息返回也不代表拖动结束。
- 旧实现依赖异步 `onMoved` 判断点击/拖动，并额外通过 16ms 轮询等待松手；消息时序不等于窗口实际位移。

## 修复

- 新增仅悬浮球可调用的 `drag_hoverbar` 命令。通过主线程调度离开 WebView IPC 回调栈，再串行执行隐藏详情、进入 Windows 原生拖动、读取最终位置及松手后吸附。
- 传入按下位置的逻辑坐标，按当前缩放换算物理抓取点，补齐 IPC 期间鼠标已产生的位移；短点击已经松手时不再启动系统拖动。
- 使用正确打包坐标的 `SendMessageW`，系统拖动返回后才结束操作，不使用逐帧 IPC 或新增常驻轮询。
- 前端按后端返回的真实位移区分点击/拖动，移除该路径的 `onMoved`、并发标记和额外吸附调用；鼠标合成 click 不再二次开关面板，键盘与菜单入口保留。
- 迟到的面板清理在后端检查拖动锁，拖动过程中不再隐藏窗口；任何正常错误返回都清理拖动状态，允许再次按下。
- 小球原有动画、光效、外观与窗口尺寸不变。未改本机 Cargo 缓存中的依赖源码，也未升级框架。

## 验证与边界

- 定向 Rust 测试验证消息坐标的打包/解包，包括左侧和上方显示器的负坐标；Rust 编译与前端 production build（含 TypeScript）通过，diff 检查通过。
- 未替换正在运行的安装包，也未完成原生鼠标实机回归。重新打包后应验收：未展开时拖动、展开瞬间拖动、已展开时拖动、连续短点击、快速重复拖动，以及四边/多屏/不同 DPI。
- 修改只影响 Windows 悬浮球拖动。原生拖动的完整体验不能由坐标单测证明；本轮不宣称已完成截图场景的实机复现验证。
- 回滚本次 Git commit 即可恢复旧拖动链路；无数据库、凭据或动画资产变更。用户已有的 `Cargo.toml` 工作区变化不包含在提交中。
