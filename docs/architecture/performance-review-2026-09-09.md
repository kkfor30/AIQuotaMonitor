## 本轮优化

- `HoverbarAnchorApp.tsx`：原来持续加载并播放约 1.20 MB 的动画 WebP。现在空闲时使用现有约 32.8 KB PNG 海报，鼠标交互、焦点、详情展开或核验状态恢复动态素材。
- `global.css`：空闲小球保持状态色并停止循环光效；系统减少动态效果时，将动画迭代次数限制为一次，避免无限动画只被压缩成 0.01ms 周期。
- `main.tsx`：按窗口标记动态加载主页面、小球、详情，公共主题和后端事件同步继续挂载。构建结果中小球独立块约 5.05 KB、详情约 41.64 KB、主页面约 662.15 KB。小球依赖链不再引入主页面块；这些是压缩前代码大小，不能换算为内存节省量。

## 后台与长期运行检查

- 额度和雷达调度每 30 秒检查到期状态，默认实际请求周期为 15 分钟；全屏监测每 2 秒一次，仅在状态翻转时改变窗口。未发现常驻忙等请求循环。
- `RefreshCoordinator` 按平台锁去重，平台之间顺序刷新、同平台 Source 并发。大量账号下仍可考虑限制 Source 并发，当前没有证据证明它是本次主要 CPU 来源。
- Codex 额度查询的 app-server 设置 `kill_on_drop(true)`，正常结束显式 kill/wait；没有从该正常路径发现每轮遗留子进程的问题。
- 三个 WebView 的 QueryClient 各自独立。`useBackendQuerySync` 收到事件直接使查询失效，隐藏且仍挂载的窗口也可能重新读取完整 ViewModel。后续可以按实际窗口可见性延迟读取，在重新显示时补齐，并对小球提供轻量摘要；需同时验证缓存新鲜度、雷达通知和重新展开状态。
- `Database::connect` 的普通路径每次打开连接。平台 ViewModel 会逐能力查询快照/趋势；`snapshot_daily_trend` 逐行处理最近 7 日历史。后续可批量查询并复用一次只读连接，减少重复连接和扫描。
- 能力快照与刷新历史没有常规定期保留策略。这是磁盘持续增长及查询成本风险，不能直接称为内存泄漏。快照被额度/重置卡观察记录以外键引用且配置 `ON DELETE CASCADE`，不得直接按日期删历史，否则可能连带删除雷达证据。本轮未清理用户数据库。
