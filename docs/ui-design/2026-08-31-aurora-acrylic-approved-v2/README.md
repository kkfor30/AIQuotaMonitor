## 固定视觉基调

### 浅色主题

- 使用低饱和冰蓝银白背景、珠光冰晶亚克力卡片、克制的磨砂和内高光。
- 主文字使用深墨蓝，说明文字保持足够对比度；禁止浅灰文字隐没在透明面板中。
- 余额金额使用清晰深蓝或冰蓝，不使用黄色、暖金或高强度发光。
- 普通卡片只保留细边、轻阴影和轻微折射，不制造整页雾状泛光。

### 深色主题

- 延续已认可的深蓝灰玻璃基底，不改成纯黑、墨绿或高饱和青绿色。
- 卡片通过略亮的深蓝层级、低对比细边和轻微内高光区分，不使用大面积霓虹。
- 主文字近白，说明、时间与单位使用清晰浅蓝灰；不得因透明度过低而隐藏。
- 金额不使用边缘光柱、金额背光或大面积局部泛光。

## 固定组件规则

### 额度行

悬浮主页统一使用：

`窗口名称 → 细进度条 → 剩余百分比 → 重置时间`

- 剩余 `>= 80%`：绿色 `#00A67D`。
- 剩余 `>= 20% 且 < 80%`：蓝色 `#0A66FF`。
- 剩余 `< 20%`：红色 `#E5484D`。
- missing 使用灰色空轨道，不补零；stale 仍按真实剩余值着色，同时展示缓存语义。

### 账户与余额

- 保留 `平台 → 账户分区 → 能力` 层级，不拆散同一平台的多个账户。
- Codex 保留 Plus 本机账户与 Free 额外账户；GLM 保留 `pro · 默认账户` 与 `lite · 个人GLM` 两个分区。
- 每个有余额的账户在分区底部使用同一种全宽财务条：左侧钱包线性图标和“个人余额”，右侧金额。
- 金额使用 tabular 等宽数字并严格右对齐；GLM、DeepSeek、Kimi、MiMo 的金额位置、字号和颜色保持一致。
- DeepSeek 的今日消费、本月消费是余额下方的次级双列数据，缓存命中率保留独立进度条，不放大成与余额争抢层级的主值。

### 状态与图标

- 平台品牌色只用于识别；健康、部分可用、错误和额度风险继续使用统一语义色。
- stale / 缓存提示使用低饱和蓝灰；橙色仅用于真实的部分可用或可能过期状态。
- 使用统一线性系统图标，禁止 Emoji、卡通钱包和传统圆形仪表盘。

## 后续生图规则

1. 主窗口新页面优先同时输出浅色、深色成对稿。
2. 悬浮页必须区分顶部/底部宽停靠与左/右侧窄停靠，不用改变平台与账户结构来适配宽度。
3. 新页面只借用本目录的材质、色阶、字体层级和组件语言，不照抄设计稿中的示例数字。
4. 不改变现有业务功能、ViewModel 字段、fresh/stale/missing 语义或四项一级导航。
5. 精准编辑时锁定已认可区域，只修改本轮明确指出的组件，避免整页重排。
