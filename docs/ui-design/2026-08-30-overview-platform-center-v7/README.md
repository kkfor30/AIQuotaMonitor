# 总览多账号卡组与平台中心只读化 V7

本目录是 2026-08-30 确认的下一轮 UI 整改基准，覆盖总览关键平台、额度进度条、额度使用趋势，以及平台中心「接入与来源」。本轮设计不改变 `Platform → Account → Source → Capability → Snapshot` 领域边界，不改变凭据安全策略，也不允许前端解析平台原始响应。

## 一、全局额度进度条规范

### 1. 固定语义

- 所有额度进度条都表示「剩余额度」，填充长度等于 remaining percent。
- 进度条旁始终展示剩余百分比文字，不能只依赖颜色。
- `80% ≤ remaining ≤ 100%`：绿色 `#00A67D`。
- `20% ≤ remaining < 80%`：蓝色 `#0A66FF`。
- `0% ≤ remaining < 20%`：红色 `#E5484D`。
- 精确边界：80% 属于绿色，20% 属于蓝色。
- `missing` 使用灰色空轨道和「未获取」，禁止当成 0%。
- `stale` 继续按最后成功剩余值着色，另加橙色「缓存」标记和最后成功时间；不要把整条进度条改成橙色。
- 余额没有总额度上限时不画进度条，只展示后端返回的金额文本，不做浮点汇总。
- 不在额度卡内增加「额度即将耗尽，请及时重置」或同义指令。0% 仅使用红色百分比、红色轨道状态和重置时间表达。需要关注区使用中性事实，例如「GLM · 个人 GLM · 7天剩余 0%」。

### 2. 组件收口

新增一个通用额度组件，例如 `QuotaProgress`，集中处理：

- `remainingPercent`、`freshness`、窗口名称、重置时间；
- 三段颜色阈值；
- `fresh / stale / missing`；
- `role="progressbar"`、`aria-valuemin/max/now`；
- 统一的百分比格式、轨道高度、圆角和文字对齐。

总览账户卡和平台中心 `CapabilityCard` 必须共用同一颜色判断。悬浮详情若未来增加进度条，也只能复用该判断；现有纯文字悬浮详情不强制增加进度条。

## 二、总览关键平台卡组

### 1. 一个平台只占一个排序位置

- `KeyPlatformWindow` 仍以 Platform 为拖拽与持久化排序单位。
- 多账号平台不拆成多张平台卡，不改变 `reorder_platforms` 的 platform id 顺序。
- 平台位置内部是账号卡组：前卡展示当前账号，后卡最多露出两层边缘和账号别名。
- 账号多于 3 个时仍只露两层，使用 `当前序号/总数` 表达，例如 `2/5`。
- 单账号平台不显示切换箭头和层叠边缘，但使用同一套账户卡内容结构。

### 2. 账号切换

- 左右箭头切换前后账号，循环或到端禁用二选一，整页保持一致；推荐到端禁用，避免用户误判顺序。
- 点击后层露出的账号边缘，直接切换到该账号。
- 箭头、后层卡边、查看详情均需阻止拖拽事件，不得触发平台重排。
- 每个平台独立维护当前账号索引；平台数据刷新时保留当前 account id，账号被移除后再回退到第一个账号。
- 切换只改变前端展示，不请求平台接口、不改变默认账号、不影响其他窗口。

### 3. 拖拽与横向浏览

- 拖拽手柄移动整个 Platform 卡组，不能只拖当前 Account 卡。
- 为避免账号切换与排序冲突，平台重排从卡头手柄开始；卡身保留滚动、选择文字和账号切换。
- 保留现有横向滚轮/触控板、卡带拖动、自动滚动、实时换位和 FLIP 落位。
- 排序 mutation 仍只提交 platform ids；不得把 account id 写入平台顺序。

### 4. 账户卡内容

按 `accountId` 聚合能力，禁止跨账号拼接：

- 窗口能力按 5 小时、7 天、30 天及其他真实窗口排序，使用统一 `QuotaProgress`。
- 同一账号同时拥有窗口和余额时，在同一账户卡底部展示余额块。
- 余额属于独立账号时，作为卡组中的独立账户卡。
- 纯余额账户显示余额主值、真实消费摘要或最后成功时间，不制造比例。
- `stale` 只标记对应能力；一个 Source 失败不得覆盖同账号其他成功能力。
- 卡底「查看全部账户」进入平台中心「额度与用量」，并定位该平台；不进入接入表单。

## 三、额度使用趋势

### 1. 命名和口径

- 删除「窗口压力趋势」名称，统一为「额度使用趋势」。
- 进度条看剩余；趋势图看已使用，二者不要混用。
- `usedPercent = 100 - remainingPercent`。
- 纵轴固定为「已使用比例」，范围 0% 到 100%。曲线越高表示使用越多。
- Tooltip 同时显示「已使用 X% · 剩余 Y%」，避免用户换算。
- 图表中不使用「压力」「平均压力」「峰值压力」等未定义口径。

### 2. 历史数据来源

- 窗口 Source adapter 继续只返回本次真实快照，不要求 adapter 自己拼趋势。
- 从 SQLite `capability_snapshots` 读取最近 7 天同一 `source_id + capability_id` 的成功快照。
- 按本地自然日分桶，每天取最后一条真实快照；缺失日期留空，不插值、不补零。
- 从 `primary_value` 读取剩余百分比，再在 Rust/ViewModel 层计算已使用比例；React 不解析平台原始响应。
- 将历史点放入现有 quota capability 的 `trend` 字段，避免再造一套重复 DTO；消费 `usage_trend` 保持原语义。
- 设计稿中的「已重置」标记只有在后端存在结构化重置时间时才显示。不能靠曲线下降猜测重置，也不能在 React 中解析说明文案。

### 3. 筛选交互

- 平台选择器只列出存在真实 quota window capability 的平台。
- 账户选择器只列出当前平台中存在窗口能力的账号。
- 默认平台为第一个存在真实窗口数据的平台；默认账号按后端 Account 顺序选择第一个可用账号。
- 切换平台后，如果旧 account id 不属于新平台，回退到新平台第一个可用账号。
- 图中同时展示当前账号真实存在的 5 小时、7 天、30 天等窗口，最多 4 条线。
- 曲线颜色用于区分窗口且保持稳定，不跟随阈值动态变色；阈值颜色仅用于剩余额度进度条。
- 无历史点时显示「暂无额度使用历史」，说明「刷新并积累真实窗口快照后展示」，不得画示例线。

## 四、平台中心「接入与来源」

### 1. 顶部只读接入概览

- 从 `PlatformCenterPage` 移除常驻 `PlatformSetupForm`。
- 顶部替换为紧凑只读 `AccessOverview`，展示官方平台名、账号数、来源数、当前 API 请求地址、最近验证和官网入口。
- 顶部不出现供应商名称、备注、API Key、Cookie、保存或取消。
- 已保存的 `user_platforms.notes` 暂时保留数据库字段，不删除、不清空；本轮只从主界面隐藏。
- D010 要求的官网链接和官方请求地址必须继续可见，不能因移除表单一起消失。

### 2. 账号与来源是唯一配置入口

- 账号标题展示账号别名、不可变类型标签（本机/默认/额外）和账号状态。
- 本机、默认、额外账号都允许修改显示别名；改名只更新 `accounts.display_name`，不能改变 account id、kind、Source、凭据目录或默认身份。
- 只有额外账号允许移除；本机和默认账号不能删除。
- 账号别名使用点击铅笔后的行内编辑：Enter/失焦提交，Esc 取消，保存中禁止重复提交。
- 来源由大卡片改为紧凑行：来源名、接入类型、凭据状态、能力数、最后成功、唯一操作。

### 3. 来源操作矩阵

| 来源类型 | 行内操作 | 点击后的行为 |
| --- | --- | --- |
| API Key | `编辑` | 打开右侧抽屉，编辑 Key 和高级请求地址，先验证再保存 |
| Web Session | `编辑` | 打开右侧抽屉，在抽屉中发起网页登录；来源行不再单独放「网页登录」 |
| Local CLI | `检测并刷新` | 直接读取本机登录并刷新，不打开编辑抽屉 |
| 不需要用户配置的本地来源 | 无或 `检测并刷新` | 不制造空抽屉 |

- 文案统一使用「编辑」，删除「编辑来源」「管理来源」和来源行的重复「网页登录」。
- 同一来源只能有一个主入口，禁止「编辑 + 网页登录」并列指向同一抽屉。

### 4. API Key 抽屉

- 标题为「编辑」，副标题为账号别名和来源名。
- 展示 API Key、获取 Key 链接和请求地址；自定义请求地址属于高级设置。
- 主要动作合并为「验证并保存」：验证成功后写入 Vault、保存请求地址、刷新该 Source、关闭抽屉并更新 Query Cache。
- 验证失败留在抽屉，保留用户未提交输入，展示后端原始错误。
- 清除凭据放在底部危险区，二次确认并说明会失去的能力。

### 5. 网页登录抽屉

- 不展示供应商名称、备注、API Key 或请求地址。
- 展示接入方式、凭据状态、能力覆盖、最后验证和最后成功。
- 主按钮为「网页登录」或「重新网页登录」。点击后打开既有隔离登录窗口。
- 抽屉展示阶段：打开登录页、等待登录、验证会话、自动保存；阶段来自真实事件，不用假进度条。
- GLM/MiMo 沿用登录成功后自动验证保存；DeepSeek 保留现有安全边界，若仍需显式验证则在捕获后显示「验证并保存」，不要伪装成已保存。
- 手动粘贴 Cookie/Token 收到「高级」折叠区，不占主路径。
- Web 登录成功后刷新对应平台 Query；登录窗口仍无 Tauri IPC 权限，Cookie/Token 不进入 ViewModel。
- 底部只保留「关闭」；自动保存型网页登录不显示常驻「保存/取消」。

## 五、实现范围与保护边界

### 必须保护

- Tauri 2 + React/TypeScript + Rust 一体结构。
- `Platform → Account → Source → Capability → Snapshot`。
- 单 Source 失败隔离、stale/missing 语义和最后成功快照。
- Decimal 金额、Windows Credential Manager、隔离登录窗权限。
- 官方 Logo、当前四项一级导航、现有平台顺序持久化。
- Grok 只有真实 7 天窗口，不能因 UI 模板补出 5 小时窗口。

### 明确不做

- 不新增 Provider 路由、代理或测速产品能力。
- 不把设计图当页面背景。
- 不使用设计稿示例数字补生产数据。
- 不新增「额度即将耗尽，请及时重置」提示。
- 不为了趋势图制造演示快照、插值或零值。
- 不做深度测试，不增加大批单元测试。

## 六、轻量验收

1. `pnpm --filter @ai-quota-monitor/desktop typecheck`
2. `pnpm --filter @ai-quota-monitor/desktop build`
3. `cargo check --manifest-path apps/desktop/src-tauri/Cargo.toml`
4. 手工查看总览：单账号、多账号、窗口+余额、纯余额、stale、missing。
5. 手工验证：账号切换不触发排序；拖拽手柄移动整个平台卡组；排序刷新后保持。
6. 手工查看平台中心：顶部无常驻编辑表单；API/Web/CLI 行动作符合矩阵；网页登录只在抽屉内发起。
7. 手工查看趋势：平台和账号切换、已使用口径、Tooltip、缺失日期和空状态。

## 七、回滚

- 设计与实现应分成可识别提交：趋势数据、总览卡组、平台中心来源页可分别回滚。
- 若账号卡组交互需要回滚，保留后端多账号 ViewModel，不回退 Account 模型，只恢复旧卡片渲染。
- 若历史趋势聚合需要回滚，停止填充 quota capability 的 `trend` 即可，不能删除已有快照。
- 若平台中心改版回滚，恢复旧页面组合即可，不能清除 `user_platforms.notes`、凭据或账号别名。
