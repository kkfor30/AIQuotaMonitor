## 页面职责

### 总览

- 只回答“当前整体是否健康、哪里需要处理、哪个窗口值得关注”。
- 不承担平台凭据配置，不复制平台中心的完整详情。
- 不把百分比、Token 和金额混到同一张趋势图。
- 点击 DeepSeek 会话失效进入“平台中心 / 接入与来源”并定位 Source。
- 点击 Kimi 未接入进入 Kimi 的接入页。
- 点击 GPT 信号进入“GPT 重置雷达 / 信号摘要”。

### GPT 重置雷达

内部固定三个 Tab：

1. 信号摘要
2. Tibo 动态
3. AI 辅助分析

V1 从 Codex Radar 公开页面同步其转载的 Tibo 英文原文，不直接访问 X。AI 是用户配置的可选解释器，不是证据来源；所有结论必须引用参与分析的原文，并保留“仅为推测，不代表官方结论”。Codex Radar 内容源、AI 分析和 Codex 额度上下文必须独立显示，任一失败不能伪造或清空其他数据。

### Tibo 动态

- 列表选择与右侧详情联动，不使用遮挡内容的弹窗。
- 列表只展示 Codex Radar 转载的 Tibo 动态，不混入其他公开账号。
- 英文原文、发布时间、X 原帖链接、Codex Radar 来源链接、同步时间和 freshness 分开显示。
- 中文翻译只用于阅读，不进入 AI 输入；Codex Radar 的上游信号标签和模型语境解读也不进入用户配置 AI。
- AI 分类必须标明“用户配置 AI 研判”；未分析时显示未分析，不使用规则或示例标签补位。

### AI 辅助分析

- AI 默认关闭；关闭后仍可查看 Tibo 原文，但不生成分析结论。
- 用户可以选择已配置的 AI 提供商、模型、分析范围并预览将发送的英文原文。
- 发给 AI 的数据仅允许英文原文、发布时间和原帖链接，不发送中文翻译、上游判断、账号、额度、凭据或 Cookie。
- 输出必须包含结论、低/中/高把握度、引用原文、支持依据、反向依据、不确定性、模型和分析时间。
- 相同原文、模型和提示词版本应复用分析结果；分析失败保留原文和上次成功结果并标记 stale。
- V1 不提供关键词规则、权重、冷却期、回测、规则版本或加入证据操作。

### 设置

二级分区收敛为：

- 通用：开机自启、浅色/深色、版本与第三方许可
- 悬浮球：显示开关、展开行为、手动/智能排序和平台顺序
- 刷新与数据：额度自动刷新间隔、本地缓存清理

平台登录和 API Key 不进入设置，统一留在“平台中心 / 接入与来源”。清除缓存只出现在“刷新与数据”，并保留二次确认。

### 悬浮球

渐进层级：

```text
小球 40×40
→ 轻展开：平台图标和关注数量
→ 平台速览：横向或纵向平台卡片
→ 平台详情 / 雷达提醒
→ 后台查看完整详情
```

悬浮球和主窗口必须消费同一份 ViewModel；悬浮球不独立刷新平台接口。GPT 卡片大字优先 5 小时窗口剩余，不展示 Credits 作主值；Credits 放在右侧 7 天窗口下方。大字不再附带「账户余额 / 5 小时窗口」小字，名称与次要值只在右侧小字行排列。

新版悬浮详情进一步收敛信息：只展示 5 小时窗口、7 天窗口、对应重置时间或个人余额，并保留 Plus/Pro/Free 等账户等级及“正常/部分可用/异常”文字状态。缓存、Token 明细、用量、赠送额度、充值额度、Credits、请求数和趋势不进入悬浮详情。同一平台同时具备 Token Plan 与个人余额时必须合并在同一卡片；GPT/Codex 等多账户平台在平台卡内按账户分组，每组独立展示套餐、窗口和账户状态，卡头展示平台聚合状态。顶部/底部停靠与左右侧停靠都保持一行一个平台，不能通过双列平台、压缩字号或裁切内容适配。

## 关键交互

1. 全部刷新只触发已配置 Source；待配置平台不发网络请求。
2. 总览关注项点击后携带 `platformId/sourceId` 定位目标，不让用户再次寻找错误位置。
3. GPT “立即检查”展示 Codex Radar 同步、原文解析和可选 AI 分析三个阶段的独立进度。
4. Tibo Feed 切换选中项只更新右侧详情，保留筛选和滚动位置。
5. AI 只分析新原文或内容、模型、提示词版本发生变化的原文；查看历史不触发重复分析。
6. 设置项默认自动保存；网络或磁盘失败时保留未提交值并提供重试。
7. 平台顺序支持按住整条平台项拖拽调整；拖动过程平滑让位，松手后一次性保存顺序。
8. 悬浮球吸附方向决定展开方向，内容顺序不因方向改变。
9. Source 失败时成功数据继续显示；缓存数据必须带 `stale` 和最后成功时间。

## 状态与颜色

- 蓝色：选中、主操作、普通数据。
- 绿色：数据新鲜或检查成功。
- 橙色：观察中、部分可用、缓存可能过期。
- 红色：明确失败或危险操作。
- 状态必须同时包含文字或图标，不能只依赖颜色。

## 示例数据说明

设计稿中的结论、把握度、Credits、Tibo 文本和时间均为交互验证数据，不代表已经存在对应后端接口。前端只能展示 ViewModel 实际返回的字段；缺失时显示未分析、missing 或未接入，不能用设计稿数字补位。

## 生成方式

本组设计使用内置 imagegen 串行生成。每一张都以前一张已确认外壳为主参考，并使用旧稿作为功能参考；旧版七项一级导航、页面职责和大段样式不应被复刻。
