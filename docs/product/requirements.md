# 产品需求

## 1. 产品目标

AIQuotaMonitor 是一个 Windows 多模型平台统一额度监控中心。用户不需要反复打开各平台官网或 CLI，就能通过桌面主窗口和屏幕边缘悬浮球快速查看额度窗口、Token Plan、余额、消费和异常状态。

首批目标平台：

- GPT / Codex
- Claude Code
- DeepSeek
- GLM
- Kimi
- MiMo
- MiniMax

后续扩展 GPT 重置雷达。V1 不直接访问 X，而是从 Codex Radar 公开页面同步其转载的 Tibo 英文原文、发布时间和原帖链接，再由用户配置的可选 AI 进行辅助分析并给出可回链原文的推测性结论。直接访问 X 作为后续可选 Source，不纳入 V1。
帖内预告时间的时区换算由确定性解析（time-v1，未标注时区按 America/Los_Angeles 并标注假设）完成；事件展示区分「预告时间已过，等待验证」「来源称已落地」「本机已观察到刷新」等时态，ambiguous 时间不得呈现为精确北京时间。

## 2. 用户价值

- 一个入口观察多个平台的真实额度和余额。
- 在悬浮球中快速判断是否需要切换平台、等待重置或处理登录问题。
- 单个平台或单数据来源失败时，不影响其他数据，也不会把最后成功值错误清零。
- 平台接入方式和数据来源可以替换，不因增删模型重做整个 UI。

## 3. 一级页面

### 总览

- 展示平台总数、正常、部分可用、待配置数量。
- 展示关键窗口和余额摘要、需要关注项、趋势和最近刷新。
- 关注项可直接跳转到平台与具体 Source。
- 不承担凭据配置，不复制平台中心完整详情。

### 平台中心

内部 Tab：

- 额度与用量
- 接入与来源

额度与用量负责查看真实数据、趋势、缓存新鲜度和刷新历史；接入与来源负责 API Key、网页登录、OAuth 或本地 CLI 状态。

平台专属要求：

- DeepSeek：余额、当日/月度消费、模型 Token、请求数、缓存命中/未命中、输出 Token、最近趋势。
- GPT/Codex：窗口额度、Credits、可重置次数和重置信号摘要。
- Claude Code：当前会话和周窗口。
- GLM/Kimi/MiniMax：Token Plan 或 Coding Plan 窗口。
- MiMo：网页登录来源与余额/额度能力。

接入规则见 [平台接入需求](./platform-access.md)：用户从产品注册表选择添加哪些平台，目录只显示已添加项。大多数平台填 API Key 即可，实现参考 cc-switch；只有官方不开放对应字段时才用网页登录。GPT / Claude Code 检测本机登录。不支持添加注册表以外的中转站。

### GPT 重置雷达

内部 Tab：

- 信号摘要
- Tibo 动态
- AI 辅助分析

V1 的内容来源固定为 Codex Radar 公开页面。Tibo 动态需要展示英文原文、发布时间、X 原帖链接、Codex Radar 来源链接、同步时间和数据新鲜度；中文翻译可以展示，但不作为 AI 输入。Codex Radar 自带的信号分类和模型语境解读不得混入用户配置 AI 输入，避免本地生成的结论只是复述上游判断。

GPT 重置雷达是事件中心，不是帖子中心。用户首先看到下一轮可能重置的时间、判断依据、本机或用户是否已确认，以及所选范围内完整 Tibo 动态。

固定数据流：CodexRadar 同步全部帖子 → Rust 区分真正新增、当前事件上下文和历史上下文 → AI 只解释新增帖子及必要上下文 → Rust 控制事件状态、时间、验证和缓存 → React 只消费脱敏 ViewModel。

三个范围必须拆开：来源同步不受 AI 开关和时间范围影响；用户查看与 AI 上下文范围只控制 Tibo 列表和背景；生命周期新增范围只包含尚未成功消费的帖子。扩大时间范围不得把已消费或已关闭事件的帖子重新激活为新事件。

AI 为用户配置的可选分析能力，默认关闭。它是原文解释器，不是证据来源；每个结论必须引用实际参与分析的 Tibo 原文。AI 开关只控制是否运行新的 AI 分析：关闭时仍同步来源、展示直接/间接/无关标签并协调本机观察，不得因此显示“暂无信号”；分析失败时新帖保持未消费，可下次重试。未启用 AI、没有真实原文、来源缺失或分析失败时，不生成推测性结论，只展示明确状态。

页面必须展示分析结论、分析依据、信号类型（重置卡 banked_reset / 额度重置 quota_reset / 无信号 none）、引用原文、支持/反向/不确定性（次要细节默认收起）、分析时间、模型标识、检查历史和“仅为推测，不代表官方结论”。重置卡与额度重置是两类独立事件，不得互相覆盖或关闭；文案按类型区分“重置卡即将到账/已到账”与“额度预计重置/已重置”。用户可对活动事件确认额度已重置或重置卡已到账并撤销。确认重置卡到账只记录人工看到卡已到账，不表示额度已刷新；确认额度已重置只记录人工看到额度落地，不判断是官方重置还是用了重置卡。后者归因请用本机验证里的“确认这是我手动使用的重置卡”。本机 observation 优先于用户确认。GPT/Codex 每个账号只读展示可用重置卡数量（真实 0 必须显示，字段缺失保持 missing，禁止补零或与额外余额换算）。V1 不实现关键词规则、权重、冷却期、回测、规则版本、使用重置卡操作或加入证据操作。

Codex Radar 来源失败时保留最后成功的 Tibo 快照并标记 stale；没有最后成功快照时显示 missing。单条动态解析失败不能清空其他已成功解析的动态。

事实归属与展示约束：

- “最近一次重置”只认本机观察（observed_reset_at）或用户确认（user_confirmed_reset_at）的事件，禁止回退来源声称时间或关闭时间；invalid_historical_replay、timeout、claimed_unverified 等普通关闭事件只能进入历史记录。仅有来源声称时展示“最近一次来源声称于 …·尚未验证”，不得称“最近一次重置”。
- 额度状态统一文案：unscheduled_reset=观察到额度重置、possible_reset=疑似额度刷新、scheduled=计划内窗口刷新、no_change=未见变化、unavailable=暂无法验证；possible_reset 不得显示为“已重置”，也不得更新“最近一次重置”。
- 当前判断依据引用只能是当前分析 citations ∩ newPostIds（radar_analyses 持久化 new/event_context/historical 三组 post id，SQLite v11）；历史上下文引用只允许出现在“最近一次重置”历史区。
- CodexRadar 公告持久化：本次未解析到公告时不清空最后一次公告，仅标记非当前；isCurrent=true 显示“CodexRadar 公告/更新 …”，否则“CodexRadar 最近公告/上次出现于 …”，从未有过显示“当前无公告”。帖子同步正常时禁止显示“暂未同步来源内容”。
- 主窗口信号摘要层级固定（UI V4）：动态范围公开显示在三个雷达 Tab 同一行（复用 analysisPrefs.rangeKey，同时控制 Tibo 列表与 AI 上下文，AI 关闭时仍可设置，AI 配置区不再重复提供范围入口）→ 当前判断/最近一次重置/本机验证三张紧凑状态卡 → AI 分析主栏 + CodexRadar 公告/Tibo 最近动态侧栏 → 最近一次重置与检查历史默认折叠。AI 结论/分析/正向依据继续消费现有真实字段；Tibo 侧栏只预览当前范围最近三条，完整列表仍在 Tibo Tab。布局参考 `docs/ui-design/2026-09-02-gpt-radar-compact-console-v4/`，设计图生成的置信度、立场和示例数据不得实现。
- AI 状态文案统一：covered=已分析（仅表示当前输入边界已有成功分析）、pending=待分析、failed=分析失败、disabled=AI 未启用、historical=历史分析、无成功结果=未分析。AI 关闭或历史态时，确定性判断与 Tibo 数据继续展示，旧结果只能作为历史结果折叠查看；切换动态范围后，旧范围分析不得继续标成当前“已分析”。
- AI 正向依据只展示当前分析 citations ∩ newPostIds 的帖子（信号类型、发布时间、可读摘要、代码解析出的北京时间、原帖链接），不显示裸帖子 ID；没有当前引用时显示“本轮没有引用重置相关帖子。”
- 悬浮摘要条收敛为：当前判断 → 最近一次真实重置 → AI 状态 → 查看详情入口；本机观察/用户确认已由判断行表达时不再重复同义状态行。悬浮详情页顺序固定：重置判断 → 公告 → AI 分析 → 本机验证 → Tibo 动态 → 最近一次重置，顶部工具栏 sticky 且 420/300px 停靠无横向溢出。

### 设置

二级分区精简为：

- 通用：开机自启、浅色/深色、版本与第三方许可
- 悬浮球：显示开关、展开时检查重置雷达、手动顺序与智能排序（套餐平台优先；切换智能时立即重排并保存）
- 刷新与数据：关闭或 3/5/15/30/60 分钟的额度自动刷新、清除本地缓存

平台登录和 API Key 不属于通用设置，统一在平台中心管理。重置雷达可手动检查，也可按用户偏好在展开悬浮详情时触发；5 分钟内不重复检查。

## 4. 悬浮球

- 40×40 小球锚点。
- 支持上、下、左、右屏幕边缘和多显示器。
- 支持小球、轻展开、平台速览、平台详情和雷达提醒。
- 支持浅色/深色、智能排序和用户手动排序。
- 全屏应用时自动隐藏，位置可记忆。
- 主窗口和悬浮球共享数据，不重复调用平台接口。

## 5. 平台与 Source 状态

平台聚合状态：

- `healthy`
- `partial`
- `setup_required`
- `error`

数据新鲜度：

- `fresh`
- `stale`
- `missing`

规则：

1. 未配置平台不发请求、不显示示例数据。
2. 一个 Source 失败不取消其他 Source。
3. 有最后成功值时继续展示并标记 stale、最后成功时间和当前错误。
4. 没有真实值时显示 missing，不允许补零。
5. 刷新按 Account/Source 去重，旧请求不能覆盖新账户或新快照。

## 6. 安全与隐私

- 前端 DTO、日志、截图和数据库不得出现完整秘密。
- Web 登录窗口不获得主窗口 Tauri IPC 权限。
- 清除凭据需要确认，并说明会失去的能力。
- 外部请求必须有超时、有限重试、限流和结构化错误。
- 金额用 Decimal；趋势缺失点与真实零值必须区分。

## 7. 非目标

MVP 不做：

- 通用 AI API 代理或自动路由。
- MCP/Skills 管理。
- 团队多租户、云同步或远程 Web 管理。
- 任意 JavaScript 用量脚本。
- 用设计稿示例数字替代真实后端数据。
